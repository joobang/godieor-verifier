# 세 저장소 작업 계획

revision: `SYNC-2026-11-09-17`. 원본 `godieor-app/docs/system/`, 다른 두 저장소는 동기화 사본.
현재 단계는 정책 결정 진행 중이다. 기존 SwiftUI 구성 유지, NestJS + PostgreSQL + Prisma, TypeORM 제외는 확정됐다.
**로컬 실행을 먼저 달성하고 최종적으로 iPhone 앱 + 클라우드 API/DB, Mac verifier로 운영한다.** 로컬 버전/도구는 확정했고 클라우드 제공자는 미정이다. 표의 완료 조건은 작업 제안이며 승인 acceptance가 아니다.

## 현재 완료와 미완료

- 완료: iOS 시작 뼈대, 앱 전용 판정기 bootstrap, 독립 리뷰 사례, 학습 카탈로그.
- 완료: backend 클론, 세 저장소 책임·의존성·정책 질문 문서화.
- 완료: 로컬 공개 API·Prisma 23 모델/초기 migration·전용 PostgreSQL·가상 제공처 수집과 문서 출처 조사.
- 완료: Prisma Client 우선 쿼리 전환·OTT 검토 후보 고정 키 매핑과 수동 publish, 로컬 실제4+가상7 조회.
- 미완료: Google/개인 쓰기·iOS API 연결·자동 전수 수집/나머지 분야 실데이터·호스팅 확정, snapshot/runner,
  evidence v2, 실제 권한 격리, 원격 배포, 승인된 정식 검증 run.

## 첫 로컬 실행 목표

확정한 작품·일정 찜과 캘린더 정책을 반영하면서, Mac의 PostgreSQL → Prisma migration/저장·재조회 →
NestJS API → Simulator 또는 본인 iPhone의 API 응답 표시를 한 흐름으로 만든다.
처음 고정 fixture를 사용하면 가상임을 명시하고 실제 제공처 연동 완료와 구분한다.
독립 검사는 Mac에서 일회용 DB·고정 snapshot으로 수행하도록 별도로 구성한다.
이 목표에는 클라우드 계정 생성·원격 배포가 포함되지 않는다.

## Google 로그인 추가 작업 제안

- APP-AUTH: Google 로그인 화면·취소/실패·재로그인/로그아웃·보호된 자격 저장.
- BE-AUTH: Google token 검증·내부 계정 식별·서비스 세션·사용자별 조회 범위. 세션 세부 정책은 추가 결정.
- VFY-AUTH: token 검증 실패/만료/audience·다른 사용자 데이터 접근·재로그인·로그아웃을 독립 검사.
- 실제 Google OAuth 클라이언트/동의 화면 설정과 실제 기기 로그인은 fixture 검사와 구분한다.
- 개인 설정·찜의 계정 저장과 재로그인/재설치 복원을 포함한다. Google 인증 사용자가 가입/이용 가능하고 사용자별 데이터 격리를 검사한다.
- 작품·일정 찜 모두 지원한다. 세션·충돌 처리와 찜 해제 의미 등 기술 세부는 구현 전 계약으로 정리한다.

## 일정 범위에 따른 추가 작업

- DATA-SCOPE: 4개 OTT와 선택 게임 기기별로 2026년 이후 실제 확보 가능한 최초 공개 일정·지역·출처를 조사한다.
- BE-RANGE: 2026-01-01부터 상한 없는 알려진 미래 일정을 기간/페이지 단위로 조회하는 계약을 만든다.
- BE-REFRESH: 초기 이력 수집과 하루 1회 정상 갱신을 분리하고, 수집 결과·마지막 성공 시각을 기록한다.
- APP-RANGE: 월 이동·카드 페이지 조회·데이터 없음/미정/출처 미지원·갱신 상태를 구분한다.
- VFY-RANGE: 2026 경계·90일보다 먼 미래·페이지 누락/중복·날짜 미정·수집 실패를 독립 예제로 확인한다.
- 위 항목은 검사/구현 계획이다. 실제 데이터 완전성 검증이나 acceptance 승인이 아니다.

## 검사 책임 matrix 초안

| 관찰할 동작 | 자체 검사 책임 | 독립 검증의 관찰점 |
|---|---|---|
| 지역/극장·OTT 분리·중복 방지 | backend domain/storage | 수집·저장·재조회 후 이벤트 수와 ID 확인 |
| 실제 시각/날짜만/미정 | backend 정규화 + app 표시 | API 값과 iOS 날짜 배치를 독립 기대값과 비교 |
| 필터 교집합 | backend API + app 선택 상태 | 요청 조건→API 결과→화면 집합, 빈 필터 정책 |
| 설정 지속성 | app persistence | 프로세스 종료·재실행 후 저장 값 재조회 |
| 일정 수정/연기/취소 | backend update + app refresh | 동일 이벤트 갱신·중복 없음·UI 상태·수집 시각 |
| 실제 제공처 접근·범위 | backend adapters | 출처별 연결 결과·지역/정밀도/라이선스 한계 |
| API/DB 호환 | backend contract + app client | 고정 두 SHA·계약·마이그레이션으로 저장→API→소비 흐름 |
| 비밀·권한 경계 | 각 구현 + 실행기 | 원본/기준 쓰기 차단·비밀 비제공·민감 로그 없음 |

기존 acceptance GD-001~010은 대응의 출발점이다. 새 backend 검사나 통합 검사 목록을
기존 파일에 조용히 덧붙이지 않고 변경안→독립 검토→사용자 승인 순서로 확정한다.

## 모든 중요 작업에 붙일 기록

- 작업 ID·requirement ID·영향 저장소·변경 전/후 동작.
- 앱/백엔드 SHA·계약/마이그레이션 digest·verifier/acceptance 버전.
- 실행한 검사와 미실행 검사·실제 결과·재현 자료.
- finding ID·해결 근거·남은 가설.
- 해당 저장소 ADR·verifier/docs/learning의 LEARN-ID 또는 기록 불필요 사유.

모든 설계 논의를 진행할 수 있다는 뜻은 아니다.

## 최초 공개 정책 반영 작업

- DATA-SCOPE/BE-RANGE: OTT 회차별 수집·이벤트 생성을 제외하고 지역/플랫폼 최초 공개 근거를 확인.
- APP-HOME: 캘린더 중심안을 적용하고 OTT 카드의 회차 번호 대신 최초 공개를 표시.
- VFY-HOME: 회차별 날짜가 최초 공개인 것처럼 들어오지 않는지, 글로벌 방영일 오인·지역별 이벤트 병합을 검사 제안.
- 시즌별 최초 공개를 포함한다. 로그인 전 캘린더·상세 조회 허용, 찜·설정 저장은 인증 필요, V1 알림 제외를 계약/화면에 반영.

## SYS-02 계약 초안 · 2026-11-09

backend/contracts에 `0.1.0-draft.2` OpenAPI·DB DDL·관계/의미·가상 응답·manifest를 작성했다.
앱과 verifier는 자체 참조 파일로 backend commit/파일 digest를 고정한다. 이 기록은 독립 검토 완료가 아니다.
다음 순서: 소비자/독립 계약 검토 → 버전/로컬 DB 도구 고정 → Prisma schema/migration과 NestJS fixture API → iOS 연결.
DDL 실행·제품 테스트·migration 적용·정식 run은 이번 계약 작성에 포함하지 않았다.

## BE-01/02 로컬 뼈대·출처 판단 · 2026-11-09

작성자 계약 검토 후 backend 초기 migration/Prisma 23 모델, 전용 PostgreSQL, Nest 공개 API와 가상 7건 수집을 실행했다.
계정 스키마는 있지만 Google/개인 쓰기·실제 제공처 연결·iOS 연결은 아직 없다. 테스트는 추가/실행하지 않았다.
현재 API·DB 구동과 수집/조회는 작성자의 실행 확인이며 독립 통합 검증 완료가 아니다.
뼈대 구성 후 공식 출처 적합성을 조사했다. backend/docs/data-source-assessment.md에서 문서 근거와 실제 키 응답 미확인을 구분한다.
다음: 본인 키·이용 조건 확인 후 KOBIS/football-data 응답 범위, TMDB 보조 데이터, IGDB 분류 매핑, OTT 최초 공개 근거 순으로 판단/연결한다.

## BE-03 계층 수정 · 2026-11-09

새 기능보다 Nest 계층 구조 정리를 우선했다. Controller/Service/Repository와 수집 Client/Adapter를 기능 모듈로 분리했다.
