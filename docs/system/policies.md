# 사용자가 결정할 정책

revision: `SYNC-2026-11-09-06`. 원본 `godieor-app/docs/system/`, 다른 두 저장소는 동기화 사본.
P01은 현재 SwiftUI·iOS 17 이상 뼈대를 유지하며 진행한다. P02의 NestJS·PostgreSQL·Prisma, TypeORM 제외는 **사용자 확정**이다.
최종 실행 위치와 로컬 우선 단계도 확정됐다. 정확한 버전·클라우드 제공자·나머지 정책은 아래 미정 범위를 따른다. 선택 제안은 사용자 확정 정책이 아니다.
P03은 계정 기반 + Google 연동 방향으로 확정했다. 기기간 동기화·세션·가입 허용 범위는 추가 결정이다.
선택 후 실제 사용자 답변과 날짜를 기록하고, 검사 방법은 별도 검토/승인한다.

## 이미 확정한 사항

GODIEOR(고디어), iOS, 영화·OTT 드라마·게임·EPL, 앱/백엔드/검증 3개 저장소,
무료 우선, 구현과 독립 검증 역할 분리, 근거를 가진 학습·선택 이력 축적.
앱·검증 저장소 공개 유지는 사용자 확정이다. backend는 생성 당시 public으로 조회됐으며 공개 범위 변경은 별도 요청 시 처리한다.

## 2026-11-09 답변 기록

사용자: “2번 pg, nest로 가자. 그리고 typeorm 말고 다른거써보자.”
따라서 framework=NestJS, database=PostgreSQL, TypeORM 제외를 확정한다.
후속 사용자 답변: “프리즈마로 간다.” 따라서 ORM=Prisma도 확정한다. Drizzle은 이전 비교 제안으로 남긴다.
DB/ORM/Node/Nest의 정확한 버전과 클라우드 제공자는 미정이다. 제품 acceptance 승인은 별도다.

후속 사용자 답변: “좋아 우리가 구성한대로 최종 구성형태로 이렇게하자. 일단 로컬 실행을 목표로가보자.”
최종 형태는 iPhone에 설치한 앱 → 클라우드 NestJS API → Prisma를 통해 클라우드 PostgreSQL이며,
verifier는 Mac에서 필요할 때 실행한다. 무료 우선이며 첫 개발 목표는 로컬 실행이다.
로컬 개발 시 API/DB/verifier는 Mac, 앱은 Simulator 또는 본인 iPhone에서 확인한다.
로컬 전용 제품으로 범위를 줄이거나 지금 원격 배포를 요청한 것으로 해석하지 않는다.
후속 사용자 답변: “로그인은 계정넣어야지. 구글 연동 하면 좋을듯?”
계정 기반 로그인과 Google 연동을 V1 방향으로 반영한다. 로그인 없는 기기 전용 계정 제안은 대체한다.
필터/찜의 서버 저장·기기간 동기화, 세션 방식/수명, 허용 Google 계정 범위, 계정 삭제/연결 정책은 아직 미정이다.

후속 사용자 답변: “커밋은 너가 필요할때마 적절히 찍어가면서 해라.”
작업 단위의 커밋은 구현 담당이 적절히 수행한다. push·원격 배포는 별도 요청 범위를 따른다.
