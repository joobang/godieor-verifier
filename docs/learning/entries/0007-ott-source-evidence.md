## 관찰과 기술적 의미

- Netflix/Coupang/CJ의 RSS는 HTTP 200과 XML 파싱까지 확인했다. 최신 일부만 있어 수집 주기와 과거 채우기는 다른 문제다.
- RSS 게시일과 작품 최초 공개일은 다른 필드다. Netflix 한국어 pubDate 문자열은 범용 날짜 파서에 그대로 기대면 안 된다.
- 공식 쿠팡 뉴스룸에도 TVING 작품이 실린다. 출처의 발행사와 작품의 플랫폼은 독립된 개념이다.
- TVING 공개 시각과 tvN 방송 시각, 일본 Disney+와 한국 Disney+를 각각 구분해야 한다.
- Disney+ 검색 색인의 정확한 날짜와 현재 상세 본문의 연도 표시가 달랐다. 검색 요약은 확정 입력 근거가 아니다.

## 선택 제안과 대안

TMDB 가용성+방영일을 공개일로 추정하는 방식은 근거가 부족하다.
통합 파트너 API는 계약/유료/coverage 확인이 필요하다. 현재 무료 전수 자동화를 입증하지 못했다.
공식 공지에서 후보를 추출하고 사람 검토 후 publish하는 방식을 제안한다. 아직 사용자가 이 운영 방식을 확정하지 않았다.
제품에 연결하기 전에 실제 반례의 독립 검사, 표본 대조, 이용 조건, 변경 이력 처리를 확인해야 한다.

## 설명·면접/블로그 초안

설명할 핵심: “HTTP로 읽을 수 있는가”, “필드 의미가 제품 요구에 맞는가”, “빠짐없이 찾을 수 있는가”를 각각 확인했다.
정상 샘플 몇 개만으로 전수 수집/정확도를 주장하지 않고 실제 반례와 미확인 범위를 문서화했다.

학습 질문: 게시일·공개일·관찰일·수정일은 왜 나누는가? 공식 도메인만 확인하면 어떤 플랫폼 오인이 발생하는가?
코드·출처·허용 조건 변경 시 이 기록과 원본 조사를 재검토한다.
