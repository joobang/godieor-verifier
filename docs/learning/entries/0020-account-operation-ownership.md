# LEARN-0020 · 세션 경계와 작업 완료 순서

2026-11-13 작성자 구현 관측/해설 초안. 원본 app `docs/ai/tasks/APP-AUTH-13.md`, ADR-003, 코드 dc3bab01d675e1fff28c8265dcf6d07606866992. 실사용자 장애·독립 승인·사용자 이해도 측정 아님.

세션 generation만 비교하면 다른 계정의 응답은 막을 수 있지만 같은 계정의 연속 저장 응답 역전과 이전 작업의 defer는 막지 못한다. 실제 AccountState에 합성 HTTP·메모리 세션·인증 결과를 주입해 네 결함을 재현했다. 늦은 v2 저장 응답이 v3를 덮고, 로그아웃 중 busy가 남고, 이전 defer가 새 계정 작업의 busy를 해제하고, 새 계정 최초 조회 실패 시 이전 설정·찜이 남았다. 수정 전11/15, 수정 후15/15를 관측했다.

busy 해제는 시작한 UUID와 현재 소유권이 같을 때만 허용한다. 설정 응답/오류는 세션뿐 아니라 시작한 mutation revision도 비교한다. 새 세션 발급 시 이전 snapshot/pending을 먼저 비우고, 로그아웃은 즉시 busy 소유권을 무효화한다. 요청 취소만으로 이미 반영된 서버 쓰기를 되돌릴 수 있다고 가정하지 않는다. 오프라인 복원은 토큰을 보존하고 재시도하며 401 만료와 구분한다.

고정 소스 unsigned iOS 컴파일은 성공했지만 UI 클릭·실 Keychain·Google·두 기기 서버 왕복을 실행한 것은 아니다. 합성 상태 검사·실행 빌드·실기기 관찰·독립 판정은 서로 다른 근거다. AccountState의 세션/저장/refresh/operation 소유권 또는 계약이 바뀌면 이 기록의 주장을 재검토한다.
