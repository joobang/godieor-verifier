# 실행 결과를 규칙 개선으로 연결

입력: 고정된 규칙 파일/digest, 최근 검증 run과 finding ledger, 관련 코드 snapshot.
규칙을 만든 구현 대화를 상속하지 않는 새 컨텍스트에서 검토한다.

- 반복 실패가 제품 구조, 검사 방법, 규칙 표현, 도구 환경 중 어디에서 생겼는지 구분한다.
- 안 읽혔거나 위반되지 않은 규칙을 곧바로 불필요하다고 단정하지 않는다. 관찰 범위와 다른 설명을 남긴다.
- 외부 기술 사실은 공식 문서와 버전으로 재확인한다. 근거가 바뀌면 기존 기록을 재검토 대상으로 표시한다.
- 신설/개정/폐지 제안마다 근거 run ID, 파일/줄, 반례, 기대 효과, 부작용을 적는다.
- 현재 실패 횟수 같은 상태는 ledger에 두고 규칙 본문에는 지속되는 판단 원칙을 둔다.
- 규칙/acceptance를 직접 수정하거나 승인하지 않는다. 사용자 승인 후 다음 버전에 반영한다.

매 작업마다 전면 감사를 하지 않는다. 같은 종류의 실패가 반복되거나 기준 충돌이 있을 때 실행한다.
