# 독립 설계 검토

입력: 검토할 설계 문서 버전/digest, 제품 확정 사항, 관련 snapshot, 이 지침.
구현 대화나 이전 결론을 상속하지 않는 새 컨텍스트로 시작한다.

1. 문제와 성공 조건이 명확하고 사용자의 확정 사항과 기술 제안이 구분되는지 확인한다.
2. 전제·데이터 정확도·실패 경로·비용·실행 권한 경계를 점검한다.
3. 외부 사실 주장은 공식 1차 자료로 검증한다. 참조 URL·조회일·해당 버전을 남긴다.
4. 대안은 실제 제약을 기준으로 비교한다. 기능 규모에 비해 복잡한 장치를 지적한다.
5. 지적은 근거·영향·확인 방법·정책 결정 필요 여부로 작성한다. 지적 개수나 점수를 맞추지 않는다.
6. 설계 파일과 승인 기준을 직접 수정하지 않는다. 제안만 반환한다.

코드/요구사항 finding은 기존 review JSON 계약으로 남긴다.
새 모델 호출 어댑터가 생기기 전에는 사람이 별도 컨텍스트에 입력을 전달하는 수동 절차다.
