# 검증 기준의 관리와 승인

`acceptance.yaml`은 YAML의 부분집합인 JSON 문법으로 저장한다. Python 표준 라이브러리로 읽을 수 있다.
현재 `0.1.0-draft`는 전달된 제품 요구사항의 **검사 초안**이며 승인 기준이 아니다.
사용자가 iOS·네 분야를 확정한 사실과, 검사 기대값·방법을 승인한 사실을 구분한다.

승인 순서:

1. 구현 담당이 변경을 제안한다. 요구사항 연결, 예시, 누락 가능성, 변경 이유를 적는다.
2. 독립 검토자가 기대값과 검사 방법을 검토한다. 앱 동작을 기준으로 기대값을 바꾸지 않는다.
3. 사용자가 해당 버전의 내용을 명시적으로 승인한다.
4. 그때 승인자·일시·사용자 승인 메시지 참조를 기록하고 별도 commit으로 보존한다.
5. 후속 변경은 새 버전으로 돌아가 동일 절차를 거친다. 버전이 같아도 파일 해시가 달라지면 재검증한다.

앱 개발 에이전트와 검증 에이전트가 직접 승인 상태를 만들어서는 안 된다.
저장소 분리 자체는 GitHub 접근 제어나 승인 권한 격리가 아니다.
향후 실행 사용자·GitHub 권한·보호 규칙이 실제로 설정되기 전에는 이를 운영상 규칙으로 설명한다.
