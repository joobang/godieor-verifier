# VFY-01 · 현재 정책과 독립 관찰점 (승인 전 제안)

acceptance.yaml 원본을 변경하지 않았다. 사용자 제품 정책과 오래된 acceptance 초안의 차이는 승인할 변경안으로 남긴다. 아래는 검증 계획이며 제품 통과 기록이 아니다.

| 요구사항 | 앱 관찰점 | backend/통합 관찰점 | 미해결 또는 후속 |
|---|---|---|---|
| GD-001 | 월·날짜 목록·페이지 누락/중복 | API 반개구간·cursor·revision 조합 | 카드 뷰 기준과 달력 우선 범위 대조 |
| GD-002 | 분야/서비스/기기 필터, 빈 분야는 표시 없음 | 같은 차원 OR, 분야 내부 서비스/기기 적용 | 기존 초안 AND 문구를 최신 정책/계약과 조정 제안 |
| GD-003 | 비로그인 임시 설정 재실행 유지 | 로그인 후 계정 저장·복원·격리 | 기기 임시 저장을 서버 roundtrip 성공으로 대입 금지 |
| GD-004 | 상세 최신 상태·일정·출처, EPL 개최국 | releaseMarket/venueCountry 의미, unknown/nullable | 정적 리뷰와 실제 UI를 별도 evidence로 |
| GD-005 | 동일 작품의 서로 다른 이벤트 보존 | 출처/지역/플랫폼별 안정 identity | 제목으로 합치지 않는 독립 fixture |
| GD-006 | 재조회 후 중복 없음 | 재수집 반복/정정·ID 보존 | 실제 제공처와 가상 검사 구분 |
| GD-007 | date_only 날짜 유지, instant 시간대 변환 | DST·범위 경계·미정 달력 제외 | 지연/409 주입 및 다양한 시간대 실행 미완료 |
| GD-008 | 상세 상태·최신성 경고·오래된 응답 방지 | 연기/취소·수집 실패 후 보존 | 최신성 허용치 승인 전 |
| GD-009 | 실데이터/가상 표시 | 네 분야 제공처 실제 계약/국가별 정확한 근거 | OTT4건은 전수 연결 근거가 아님 |
| GD-010 | 빌드·번들 비밀 검사 | 서버 키 보관·로그 민감정보 검사 | 실행과 비밀 검사를 각각 수집 |

VFY-02는 위 검사의 정확한 대상 조합을 식별하는 형식을 제공한다. runner 구현(VFY-03/04) 및 INT-01 실행 전 위 표의 관찰점이 자동 검증된다고 표현하지 않는다. acceptance의 필수 검사/심각도/승인 상태는 유지한다.
